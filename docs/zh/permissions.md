# 權限：誰可以做甚麼

在 **People & access（人員與權限）** 管理使用者角色、群組及職銜。在資料夾或文件的 **Permissions（權限）** 管理指定內容的存取。在 [PII 與角色遮蔽](pii.md) 設定哪些資料不能讓某個角色看到。

| 控制 | 決定甚麼 | 在哪裡檢查 |
|---|---|---|
| 公司模組 | 這家公司有沒有開啟某項功能 | 頁面顯示未啟用時，向公司管理員確認 |
| 使用者權限 | 此人能否上載、覆核、下載或修改設定 | 人員與權限 → 使用者 → **Info**／權限 |
| 資料夾及文件規則 | 此人能否存取這個資料夾或文件 | Drive → **權限** → 有效權限 |
| 角色遮蔽 | 此角色可以收到哪些欄位值 | 設定 → **PII** 及 **角色遮蔽** |
| 流程參與者 | 這一步要由誰審批 | 流程設定及該步驟的指定參與者 |

授予使用者權限不會同時開啟公司模組，也不會自動把該人加入審批流程。可以打開文件，亦不代表可以看到所有敏感欄位。

## 先確認使用者角色

以下是內置角色的預設。自訂角色、群組／職銜角色和個人例外設定會影響最終結果。

| 能力 | Uploader（上載者） | Compliance / Reviewer（合規／覆核者） | Admin（管理員） |
|---|---|---|---|
| 瀏覽及處理 Drive 檔案 | 有 | 有 | 有 |
| 管理處理佇列 | 有 | 有 | 有 |
| 使用助理 | 有 | 有 | 有 |
| 安全下載 | 有 | 有 | 有 |
| 覆核文件 | 無 | 有 | 有 |
| 查找浮水印／執行工作台動作 | 無 | 有 | 有 |
| 用助理草擬電郵 | 無 | 無 | 有 |
| 修改公司設定 | 無 | 無 | 有 |

以上能力仍受公司模組及相關文件控制限制。**Uploader 並非唯讀角色。** 若某人只應讀取及下載，請建立只包含這些權限的自訂角色。

1. 打開 **人員與權限**，找到使用者。
2. 檢查角色、群組和職銜。群組及職銜也可以附帶角色權限。
3. 按 **Info**，查看使用者角色、各個群組／職銜角色、個人例外，以及 **Effective permissions（有效權限）**。
4. 修改相關角色、成員關係或例外設定；編輯器提供 **儲存** 時，按儲存才套用。
5. 讓使用者重新載入或重新登入，再用該帳戶測試所需操作。

新增人員及部門請參閱 [人員與權限](people.md)。變更管理員請參閱 [更換管理員](change-admin.md)。

## 自訂角色、Union 與 Intersect

從人員與權限或設定打開 **Custom Roles（自訂角色）**。輸入名稱、選擇可用的基礎角色、勾選權限並建立，再指派給使用者或相關群組／職銜。單純建立角色不會改變任何人的存取權。

| 選項 | 作用 |
|---|---|
| 群組／職銜的 **Union（聯集）** | 把該角色的權限加入使用者的組合權限 |
| 群組／職銜的 **Intersect（交集）** | 只保留該角色也有的權限；所有交集限制都在聯集之後套用 |
| 個人 **Grant（授予）** | 加入一項權限，但仍受 Intersect 限制 |
| 個人 **Deny（拒絕）** | 移除該權限；其他 Union 不會把它加回來 |
| 個人 **Inherit（繼承）** | 移除該人的例外，使用角色及成員關係的結果 |

例如某群組以 **Union** 加入文件覆核權限，但另一個 **Intersect** 角色只保留讀取及下載，最終仍沒有覆核權限。請用 **Info** 確認結果，不要只看角色名稱。

## 資料夾及文件權限

在 **Drive** 選取資料夾或文件，打開 **Permissions（權限）**。有管理權的帳戶亦可在文件預覽內打開權限區塊。

1. 選 **Add a rule（新增規則）**。
2. 選擇 **allow（允許）** 或 **deny（拒絕）**。
3. 選擇編輯器提供的動作，例如檢視、編輯、下載、刪除、列印或複製。
4. 選擇對象類型：**角色**、**使用者** 或 **部門**，再選名稱。
5. 加入規則。在有效權限檢視器選取要檢查的使用者。

檢視器會說明哪一條規則決定結果。優先次序如下：

1. **Admin 可略過資料夾／文件規則。** 管理員操作有稽核紀錄；測試限制時請使用非管理員帳戶。
2. 文件本身的規則優先於資料夾規則；較近的上層資料夾優先於較遠的上層。
3. 在相同範圍內，指定使用者優先於部門，部門優先於角色。
4. 同樣明確的規則互相衝突時，**deny** 優先。
5. allow 不會超過使用者內置基礎角色的文件動作上限；自訂角色／個人授權不會取消這個上限。
6. 沒有符合的規則時，按內置基礎角色能力處理；**複製** 需要明確 allow。

例子：Finance 資料夾對 Uploader 拒絕檢視，但其中一份文件對 Uploader 允許檢視，該文件的例外優先。如果同一文件另有對某位使用者的 deny，該人的明確拒絕會優先於角色 allow。

只對某部門新增 allow，**不會自動拒絕其他所有人**。請加上需要的較廣範圍 deny，並分別檢查獲准者及被排除者。刪除一條規則會恢復繼承／預設結果，不等於拒絕存取。

## 結果與預期不同時

| 情況 | 檢查甚麼 |
|---|---|
| 整項功能顯示未啟用 | 公司模組；只改使用者角色不會開啟模組 |
| 按鈕消失或停用 | Info 的有效權限，以及功能／文件狀態要求 |
| 只有某資料夾或文件不能打開 | 有效權限、繼承規則及指定使用者規則 |
| 可以打開文件，但欄位顯示 `[REDACTED]` | PII 及角色遮蔽兩邊的設定 |
| 遮蔽測試好像沒有作用 | 使用目標非管理員角色測試；Admin 不受角色遮蔽限制 |
| 新增 allow 後仍不能操作 | 更明確的 deny、Intersect 限制，或基礎角色的文件動作上限 |
| 使用者未收到指定審批 | 流程參與者及當前步驟，與一般覆核權限分開檢查 |

到 [稽核](audit.md) 查看已記錄的變更和文件操作，可用 **Who** 及 **What** 篩選縮小範圍。
