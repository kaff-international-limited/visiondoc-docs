# 權限：誰可以做甚麼

在 **People & access（人員與權限）** 管理使用者角色、群組及職銜。在資料夾或文件的 **Permissions（權限）** 管理指定內容的存取。在 [PII 與角色遮蔽](pii.md) 設定哪些資料不能讓某個角色看到。

| 控制 | 決定甚麼 | 在哪裡檢查 |
|---|---|---|
| 公司模組 | 這家公司有沒有開啟某項功能 | 頁面顯示未啟用時，向公司管理員確認 |
| 使用者權限 | 此人能否上載、覆核、下載或修改設定 | 人員與權限 → 使用者 → **Info**／權限 |
| 資料夾及文件規則 | 此人能否存取這個資料夾或文件 | Drive → **權限** → 有效權限 |
| 角色遮蔽 | 此角色可以收到哪些欄位值 | 設定 → **PII** 及 **角色遮蔽** |
| 流程參與者 | 這一步要由誰審批 | 流程設定及該步驟的指定參與者 |

授予使用者權限不會同時開啟公司模組，也不會自動把該人加入審批流程。可以打開文件，亦不代表可以看到所有敏感欄位。

## 使用者權限：10 項中英對照

權限代碼是系統識別值，不會隨語言改變。以下列出英文名稱、中文意思和代碼；畫面仍顯示英文或代碼時，可用這裡對照。勾選一項不代表同時擁有其他項目，亦不代表可以存取所有文件。

| 英文名稱 | 中文名稱 | 權限代碼 |
|---|---|---|
| Read drive/documents | 讀取雲端／文件 | `drive:read` |
| Write/upload documents | 寫入／上載文件 | `drive:write` |
| Manage processing queue | 管理處理佇列 | `queue:manage` |
| Review & approve | 審核及批准 | `review` |
| Edit settings (admin) | 編輯設定（管理員） | `settings:edit` |
| Watermark leak lookup | 浮水印外洩查詢 | `watermark:lookup` |
| Use AI assistant | 使用 AI 助手 | `assistant:use` |
| AI email drafting | AI 電郵草擬 | `assistant:email_draft` |
| Run workbench skills | 執行工作台技能 | `workbench:run` |
| Secure download/print | 安全下載／列印 | `download:secure` |

### 1. 讀取雲端／文件 — drive:read

用於讀取文件庫清單、搜尋結果和文件資料。例如員工要打開文件庫找一份發票，就需要這項能力。實際可見的文件仍要按資料夾／文件存取規則判斷。

**不包含：** 上載、修改、刪除、審核或下載權限。可以檢視的擷取欄位仍可能受 PII 遮蔽。一般使用情況下，還要檢視或修改文件的人亦需要這項讀取權限。

### 2. 寫入／上載文件 — drive:write

用於新增／上載文件，以及文件庫的寫入操作，例如重新命名、移動、刪除和建立資料夾。具體操作仍有自己的文件規則、狀態或保留政策要求。

例如文員可以上載發票及整理資料夾，但不因此成為發票審批人。這是一組寫入能力，**不是只限「上載」的開關**；不要把它當成純上載而不能改動現有文件的角色。

線上編輯亦需要此項，並須符合支援格式、編輯服務和角色遮蔽要求。它不會授予公司設定或工作流程審批權。

### 3. 管理處理佇列 — queue:manage

這是權限目錄中預留的處理佇列管理項目。**現行版本未把所有佇列／重新處理操作接到此獨立權限，不能只取消它就當作已禁止重新處理。**

例如「重新執行標籤及規則」等管理操作目前檢查 `settings:edit`；單份文件的重新 OCR 檢查 `review`。上載則檢查 `drive:write`。要限制某個操作，請按實際功能及有效權限檢查，不能只看這項的名稱。它亦不代表可以審批文件。

### 4. 審核及批准 — review

用於文件審核，例如批准、拒絕，以及文件狀態容許的釋放、封存等審核動作；亦用於相關擷取資料修正和單份文件重新 OCR。

例如合規同事檢查一份待覆核文件後作出決定。**一般文件審核不等於工作流程簽批。** KM 或其他流程仍按當前步驟、指定使用者／角色及流程規則決定誰可以處理；單給 `review` 不會讓此人批准所有申請。文件狀態亦可能令某個審核動作不可用。

### 5. 編輯設定（管理員） — settings:edit

用於修改公司的設定，以及受此權限保護的人員、角色、個人權限、規則、PII／遮蔽及其他管理功能。這項會影響整個公司的操作方式；應授予需要管理公司設定的人。

例如管理員調整角色遮蔽政策，或為某位同事設定個人權限例外。**取得這項不會把使用者的基礎角色變成 Admin，也不會自動取得平台營運權限或開啟公司模組。** 特定功能仍可能另外要求管理員身份、已啟用的模組或其他條件。

### 6. 浮水印外洩查詢 — watermark:lookup

用於查看及查找浮水印識別碼的關聯紀錄，例如查出某份帶有浮水印的輸出與哪位使用者、輸出渠道和文件相關。

例如合規同事按浮水印識別碼查核輸出來源。這項**不等於可修改浮水印政策、發行識別碼或管理所有設定**；這些管理動作另外要求設定權限。浮水印用於追蹤，並不遮住敏感內容。

### 7. 使用 AI 助手 — assistant:use

用於向 AI 助手提問。讀取文件內容還需要 `drive:read`；草擬電郵和工作台功能亦有各自的權限。

例如員工問文件相關問題，需要助手權限及相關文件讀取條件。只勾選這項**不會同時啟用所有 AI 功能、解除 PII 遮蔽或開啟公司尚未啟用的服務**。

### 8. AI 電郵草擬 — assistant:email_draft

用於 **Draft email（草擬電郵）**。必須同時具有 `assistant:use`、`drive:read` 和這項權限；選取的文件也須可存取。涉及下載附件時，還要符合下載權限。

例如以已選文件產生主旨和正文，讓使用者檢查及修改。**此功能產生草稿，不會自動寄出電郵。** 它亦不是工作流程通知的寄送權限；工作流程通知由相應流程設定控制。

### 9. 執行工作台技能 — workbench:run

用於列出及執行工作台提供的技能，並查看工作台產生的成果。畫面可能保留 **Workbench（工作台）** 這個名稱。

例如使用工作台的文件草擬功能。技能如果需要文件或 AI 助手，仍要分別符合 `drive:read` 或 `assistant:use` 等要求。**能與助手對話，不代表能執行工作台技能；反過來亦一樣。** 可用技能亦取決於目前版本及公司服務。

### 10. 安全下載／列印 — download:secure

用於受控下載及列印輸出。文件層面的 `download`／`print` 規則會分別判斷能否下載或列印；輸出仍要符合文件狀態、浮水印及角色遮蔽政策。

例如員工獲准下載一份文件，得到的仍可能是遮蔽後或帶浮水印的版本。這項**不是下載未遮蔽原檔的豁免權**。無法安全產生輸出時，系統可以拒絕提供。

## 內置角色的預設權限

以下是尚未套用自訂角色、群組／職銜及個人例外的預設。**有** 表示該權限代碼在角色清單內，不代表公司功能已啟用或所有文件都可以操作。

| 權限 | Uploader（上載者） | Compliance / Reviewer（合規／覆核者） | Admin（管理員） |
|---|---|---|---|
| 讀取雲端／文件 | 有 | 有 | 有 |
| 寫入／上載文件 | 有 | 有 | 有 |
| 管理處理佇列（見上述現有限制） | 有 | 有 | 有 |
| 審核及批准 | 無 | 有 | 有 |
| 編輯設定 | 無 | 無 | 有 |
| 浮水印外洩查詢 | 無 | 有 | 有 |
| 使用 AI 助手 | 有 | 有 | 有 |
| AI 電郵草擬 | 無 | 無 | 有 |
| 執行工作台技能 | 無 | 有 | 有 |
| 安全下載／列印 | 有 | 有 | 有 |

**Uploader 並非唯讀角色。** 若某人只應讀取及下載，可用 Uploader 作基礎，建立包含 `drive:read`、`download:secure` 的自訂角色，再檢查群組、職銜和個人例外有沒有加入其他能力。不要用 Admin 基礎角色測試受限帳戶，因為 Admin 可略過文件規則及角色遮蔽。`reviewer` 是 `compliance` 的別名，並非第四種內置角色。

## 如何檢查及修改一個人的權限

1. 打開 **人員與權限**，找到使用者。
2. 檢查角色、群組和職銜。群組及職銜也可以附帶角色權限。
3. 按 **Info（資料）**，查看使用者角色、各個群組／職銜角色、個人例外，以及 **Effective permissions（有效權限）**。
4. 修改相關角色、成員關係或例外設定；編輯器提供 **儲存** 時，按儲存才套用。
5. 讓使用者重新載入或重新登入，再用該帳戶測試所需操作。

新增人員及部門請參閱 [人員與權限](people.md)。變更管理員請參閱 [更換管理員](change-admin.md)。

## 自訂角色、Union 與 Intersect

從人員與權限或設定打開 **Custom Roles（自訂角色）**。輸入名稱、選擇可用的基礎角色、勾選權限並建立，再指派給使用者或相關群組／職銜。單純建立角色不會改變任何人的存取權。

| 選項 | 作用 |
|---|---|
| 群組／職銜的 **Union（聯集）** | 把該角色的權限加入使用者的組合權限 |
| 群組／職銜的 **Intersect（交集）** | 只保留該角色也有的權限；所有交集限制都在聯集之後套用 |
| 個人 **Grant（授予）** | 加入一項權限，但仍受 Intersect 限制 |
| 個人 **Deny（拒絕）** | 移除該權限；其他 Union 不會把它加回來 |
| 個人 **Inherit（繼承）** | 移除該人的例外，使用角色及成員關係的結果 |

例如某群組以 **Union** 加入文件覆核權限，但另一個 **Intersect** 角色只保留讀取及下載，最終仍沒有覆核權限。請用 **Info** 確認結果，不要只看角色名稱。

## 資料夾及文件權限：6 個動作

使用者權限決定「這人有甚麼能力」，這裡的規則則針對「這份文件或這個資料夾」。例如 `download:secure` 是使用者能力，`download` 是某份文件的下載動作，兩者不是同一項。

| 英文／動作代碼 | 中文 | 控制及例子 | 不能當作甚麼 |
|---|---|---|---|
| `view` | 檢視 | 文件／資料夾是否可供檢視；例如只讓指定部門看到財務資料夾 | 不會同時授予編輯、下載或查看未遮蔽資料 |
| `edit` | 編輯 | 文件庫的更改操作；例如重新命名、移動文件，以及目的資料夾是否容許寫入 | 不是公司設定權限；線上編輯另見下方限制 |
| `copy` | 複製 | 權限編輯器中的複製動作；非 Admin 在沒有符合規則時預設不允許，需要明確 allow | 現行版本未以它統一控制所有複製途徑；不能視為禁止下載後複製、截圖或作業系統剪貼簿的保證 |
| `delete` | 刪除 | 是否可刪除指定文件／資料夾；例如限制一般同事刪除合約 | 不是刪除任何文件的豁免權；保留期、封存及文件狀態仍可能阻止操作 |
| `print` | 列印 | 是否容許 VisionDoc 的受控列印輸出；例如容許檢視，但拒絕列印 | 不是對已下載檔案或外部軟件的遙距列印控制 |
| `download` | 下載 | 是否可取得該文件的下載輸出；例如文件可檢視，但不容許下載 | 不會解除 PII／角色遮蔽，也不會讓收件人取得系統內其他文件 |

**編輯的現有限制：** 線上編輯另外檢查寫入能力、文件狀態、編輯服務及角色遮蔽；目前不能只靠文件的 `edit` 規則作為停用線上編輯的控制。需要某人完全不能寫入時，亦應檢查其 `drive:write` 有效權限，再測試實際使用的操作。

文件規則按內置基礎角色套用動作上限：`view` 對應讀取；`edit`、`delete` 對應寫入；`copy`、`print`、`download` 對應安全下載。功能本身仍可以另外檢查有效使用者權限，因此文件規則顯示「允許」不一定代表整個操作已符合所有條件。

### 設定一條規則

在 **Drive** 選取資料夾或文件，打開 **Permissions（權限）**。有管理權的帳戶亦可在文件預覽內打開權限區塊。

1. 選 **Add a rule（新增規則）**。
2. 選擇 **allow（允許）** 或 **deny（拒絕）**。
3. 選擇編輯器提供的動作，例如檢視、編輯、下載、刪除、列印或複製。
4. 選擇對象類型：**角色**、**使用者** 或 **部門**，再選名稱。
5. 加入規則。在有效權限檢視器選取要檢查的使用者。

檢視器會說明哪一條規則決定結果。優先次序如下：

1. **Admin 可略過資料夾／文件規則。** 管理員操作有稽核紀錄；測試限制時請使用非管理員帳戶。
2. 文件本身的規則優先於資料夾規則；較近的上層資料夾優先於較遠的上層。
3. 在相同範圍內，指定使用者優先於部門，部門優先於角色。
4. 同樣明確的規則互相衝突時，**deny** 優先。
5. allow 不會超過使用者內置基礎角色的文件動作上限；自訂角色／個人授權不會取消這個上限。
6. 沒有符合的規則時，按內置基礎角色能力處理；**複製** 需要明確 allow。

例子：Finance 資料夾對 Uploader 拒絕檢視，但其中一份文件對 Uploader 允許檢視，該文件的例外優先。如果同一文件另有對某位使用者的 deny，該人的明確拒絕會優先於角色 allow。

只對某部門新增 allow，**不會自動拒絕其他所有人**。請加上需要的較廣範圍 deny，並分別檢查獲准者及被排除者。刪除一條規則會恢復繼承／預設結果，不等於拒絕存取。

| 英文 | 中文 | 意思 |

| Role / User / Department | 角色／使用者／部門 | 文件規則套用的對象 |

| Grant / Deny / Inherit | 授予／拒絕／繼承 | 個人權限的加入、移除或取消例外 |

## 常見設定例子

| 需求 | 如何設定及檢查 |
|---|---|
| 同事只需要讀取及下載 | 自訂角色包含 `drive:read`、`download:secure`；檢查有沒有其他來源加入寫入能力，再檢查目標文件規則及遮蔽 |
| 同事需要上載及整理文件 | 讀取及寫入能力；說明寫入亦包含重新命名、移動和刪除等操作，再按文件規則限制範圍 |
| 合規同事需要審核文件 | 讀取及 `review`；如果是流程審批，另檢查指定參與者與步驟 |
| 同事需要草擬電郵 | 同時有 `assistant:email_draft`、`assistant:use`、`drive:read`，並可存取選取文件；生成後仍須由人檢查草稿 |
| 只讓財務部看到資料夾 | 設定適當的較廣範圍檢視 deny，再加財務部 allow；檢查較明確的文件／使用者規則，並以非 Admin 帳戶測試 |

## 結果與預期不同時

| 情況 | 檢查甚麼 |
|---|---|
| 整項功能顯示未啟用 | 公司模組；只改使用者角色不會開啟模組 |
| 按鈕消失或停用 | Info 的有效權限，以及功能／文件狀態要求 |
| 只有某資料夾或文件不能打開 | 有效權限、繼承規則及指定使用者規則 |
| 可以打開文件，但欄位顯示 `[REDACTED]` | PII 及角色遮蔽兩邊的設定 |
| 遮蔽測試好像沒有作用 | 使用目標非管理員角色測試；Admin 不受角色遮蔽限制 |
| 新增 allow 後仍不能操作 | 更明確的 deny、Intersect 限制，或基礎角色的文件動作上限 |
| 使用者未收到指定審批 | 流程參與者及當前步驟，與一般覆核權限分開檢查 |

到 [稽核](audit.md) 查看已記錄的變更和文件操作，可用 **Who（誰）** 及 **What（甚麼操作）** 篩選縮小範圍。
