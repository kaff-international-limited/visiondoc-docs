# PII 與角色遮蔽

PII 指可識別個人的資料，例如身份證號碼、電話及電郵。VisionDoc 亦可保護已擷取的業務欄位，例如銀行戶口和聯絡人資料。

**偵測** 從文件文字找出資料；**遮蔽** 決定某角色可以收到哪些值；**浮水印** 在輸出加上標記，並不隱藏內容。[文件權限](permissions.md) 則控制能否存取文件本身。

## 設定公司的 PII 選項

1. 使用有公司設定編輯權的帳戶登入。
2. 打開 **設定 → PII**。
3. 勾選要隱藏的類別。
4. 按 **儲存**。只改勾選而未儲存，政策不會套用。
5. 使用受影響的非管理員帳戶打開測試文件，檢查實際需要的擷取欄位、預覽及下載。

勾選的選項會為 **Uploader** 及 **Compliance** 加入遮蔽規則，**不會遮蔽 Admin**。自訂角色仍有內置基礎角色；單純改角色名稱不會建立新的遮蔽類別。

| PII 選項 | 涵蓋內容 |
|---|---|
| 遮蔽電郵 | 偵測到的電郵地址，以及供應商電郵擷取欄位 |
| 遮蔽電話 | 偵測到的電話，以及供應商電話欄位 |
| 遮蔽身份證號碼 | 支援的 HKID 偵測器；並非所有國家證件格式的通用偵測器 |
| 遮蔽銀行戶口號碼 | 戶口號碼、末四位及戶口名稱，包括銀行戶口欄位的別名 |
| 遮蔽銀行名稱 | 已擷取的銀行名稱欄位 |
| 遮蔽商業登記號碼 | 已擷取的供應商及客戶商業登記號碼 |
| 遮蔽送貨及帳單地址 | 這兩個已擷取的地址欄位 |
| 遮蔽聯絡人及客戶名稱 | 這兩個已擷取的名稱欄位 |

欄位選項針對指定的擷取欄位，不代表可以自動找出圖片中任何位置、任何格式的所有地址、名稱或登記號碼。文件清晰度及擷取準確度會影響偵測結果。

**現行版本有兩項要特別分清：**

- **Allow compliance roles to preview unmasked (placeholder)** 已標示為 placeholder，並非已實作的遮蔽例外。不要用它授予受保護資料的檢視權。
- PII 卡片的 **Retention days** 是已儲存的設定，不是文件刪除政策。實際文件生命週期請在 [保留期與法律封存](retention.md) 設定。

## 用角色遮蔽建立更具體的規則

打開 **設定 → Role Masking（角色遮蔽）**。例如只想向上載者隱藏銀行戶口，而讓 Compliance 看見，可在這裡設定。

1. 按 **Add rule（新增規則）**。
2. 按下表選擇類型及目標。
3. 在 **Hidden from（不讓以下角色看見）** 勾選 **uploader**、**compliance** 或兩者。
4. 按 **儲存**。每條規則都要有目標及至少一個受限制角色。
5. 分別用受影響角色測試。Admin 不會出現在可拒絕的角色選項。

| 規則類型 | 目標 | 例子 |
|---|---|---|
| PII 類型 | `HKID`、`PHONE`、`EMAIL`、`BANK_ACCOUNT` | 對 uploader 隱藏 `BANK_ACCOUNT` |
| 擷取欄位 | 欄位內部名稱，不是顯示標籤 | 對 uploader 隱藏 `total_amount` |
| 文字模式 | 有效的正則表達式 | 隱藏公司文件中的指定文字模式 |

**欄位名稱規則會遮蔽擷取欄位的值，但單靠這條規則，不會在原檔中定位及移除同一個值。** 檔案內容遮蔽使用支援的 PII 偵測器及文字模式規則。若不應提供原檔，亦要設定相關文件／下載權限並驗證輸出。

請使用擷取結構中的正確欄位鍵值。若只看見友善顯示名稱，向管理擷取結構的人確認。修改顯示標籤不會改變內部欄位名稱。

如可使用 AI 草擬，輸入政策描述並按 **Generate draft**。生成的規則會取代編輯器內尚未儲存的內容；逐條檢查後，再按 **儲存** 才套用。只生成草稿不會改變現行政策。

### 例子：只限制上載者

假設公司要求 Compliance 可以看銀行戶口，但上載者不可以：

1. 先檢查 **設定 → PII**。若已勾選銀行戶口遮蔽，會同時限制兩個角色。
2. 如果公司核准的政策容許 Compliance 查看，取消這個廣泛選項並儲存。
3. 到 **角色遮蔽** 加入 `BANK_ACCOUNT`，Hidden from 只勾選 **uploader**。需要時亦加入戶口名稱等欄位規則。
4. 儲存後，用合成測試文件分別以 uploader 和 compliance 驗證。

PII 選項和角色遮蔽規則會合併生效。移除其中一項限制，不會取消另一條仍然隱藏相同值的規則。這裡沒有可以蓋過遮蔽 deny 的 allow 規則。

## 打開及下載文件時如何運作

系統按使用者的內置基礎角色套用公司遮蔽政策。受保護欄位可能顯示為 `[REDACTED]`。遮蔽不會從儲存的原檔刪除那些資料。

對支援的 PII 類型及文字模式規則，伺服器亦會檢查受保護的文件輸出：

- 支援的文字檔及有文字層的 PDF，可在回傳的輸出移除受限制值；PDF 遮蔽後會再次檢查。
- 純圖片掃描、不支援的格式，或不能安全遮蔽的 PDF，可能拒絕向該角色提供。
- 若下載路徑有合適的已擷取文字，且未發現受限制值，某些不能改寫內容的格式仍可原樣提供。不要假設所有 Office 文件一定被封鎖，或一定可以下載。
- 線上編輯需要原檔內容；只要有適用於該角色的遮蔽政策，編輯 session 會被拒絕，即使該人可以看遮蔽後的結果。

**Admin 不受角色遮蔽限制。** 管理員看見完整值不代表政策失效。Compliance 身份亦不會自動略過明確限制 compliance 的規則。

## 使用前如何驗證

準備含合成資料的測試文件，並用兩個獨立帳戶：管理員和目標受限使用者。檢查團隊實際使用的欄位、預覽、下載／匯出及編輯路徑。確認管理員仍能管理文件、受限使用者得到預期的遮蔽或拒絕，而無關欄位仍可使用。

若某值仍然可見，檢查欄位鍵值、偵測類型／模式、兩個政策頁及使用者的基礎角色。若下載被拒絕，先看原因；該格式可能不能安全遮蔽。不要只為了完成下載而關閉公司的保護政策。

角色及文件存取請看 [權限](permissions.md)；各項設定入口請看 [設定](settings.md)；操作紀錄請看 [稽核](audit.md)。
